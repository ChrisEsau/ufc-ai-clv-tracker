# UFC Outcome Schema Specification

## Purpose

This document defines the canonical outcome-based schemas for the UFC prediction, market, and betting pipeline.

It supports the approved V2 architecture documented in:

```text
docs/UFC_PREDICTION_PIPELINE_V2.md
```

If this document conflicts with older side-based prediction or betting-board docs, this document and `UFC_PREDICTION_PIPELINE_V2.md` should be treated as the target architecture.

---

## Core Principle

The canonical unit of prediction, odds, betting decisions, CLV, and Model Lab comparison is:

```text
one row per fight / market / outcome / model
```

Not:

```text
one row per fight with red_* and blue_* columns
```

Moneyline, prop, method, totals, and round markets should all use the same outcome-row pattern.

---

## Naming Standards

### Common IDs

| Field | Meaning |
|---|---|
| `event_id` | Canonical event identifier when available. |
| `fight_id` | Canonical fight identifier. Required for joining prediction and odds outcomes. |
| `model_id` | Unique model identifier from the model registry. |
| `market_key` | Canonical market identifier, such as `moneyline`, `goes_distance`, or `method`. |
| `outcome_label` | Canonical bettable outcome label. |

### Market Key Examples

```text
moneyline
goes_distance
inside_distance
ko_tko
submission
decision
method
over_under_2_5
round_1_finish
```

### Outcome Label Examples

Moneyline:

```text
Islam Makhachev
Dustin Poirier
```

Goes distance:

```text
goes_distance
inside_distance
```

Method:

```text
ko_tko
submission
decision
```

Totals:

```text
over_2_5
under_2_5
```

Outcome labels must be canonicalized before joins. Provider-specific labels from odds APIs should be normalized to the same labels generated by the prediction formatter.

## Data Type Conventions

| Type | Convention |
|---|---|
| ID fields | string when persisted, even if originally numeric. |
| timestamps | ISO 8601 UTC string or timezone-aware timestamp. |
| probabilities | decimal probability from `0.0` to `1.0`. |
| percentages | avoid storing percentage values unless explicitly suffixed with `_pct`. |
| American odds | numeric integer or float, e.g. `-150`, `+120`. |
| decimal odds | numeric decimal, e.g. `1.67`, `2.20`. |
| boolean fields | true/false. |
| money/EV fields | numeric value per configured stake basis. |

Preferred probability field names:

```text
model_probability
implied_probability
```

Avoid storing core probabilities as `72` for 72%. Store as `0.72`.

## Canonical Prediction Outcome Schema

Recommended path:

```text
data/predictions/model_outcomes.parquet
```

Recommended model-scoped path:

```text
data/predictions/by_model/{model_id}/model_outcomes.parquet
```

### Primary Grain

```text
one row per prediction_run_id / model_id / fight_id / market_key / outcome_label
```

### Required Columns

| Column | Type | Description |
|---|---:|---|
| `prediction_run_id` | string | Unique prediction run identifier. |
| `prediction_timestamp` | timestamp/string | UTC time when predictions were generated. |
| `model_id` | string | Model ID from registry. |
| `model_family` | string | Model family, such as `moneyline` or `goes_distance`. |
| `algorithm` | string | Algorithm name, such as `xgboost`. |
| `prediction_type` | string | Formatter type: `binary_matchup`, `binary_prop`, `multiclass`, etc. |
| `event_id` | string | Event identifier when available. |
| `event_name` | string | Human-readable event name. |
| `fight_id` | string | Fight identifier. |
| `red_fighter` | string | UFCStats red-side fighter name. |
| `blue_fighter` | string | UFCStats blue-side fighter name. |
| `red_fighter_id` | string | UFCStats red-side fighter ID. |
| `blue_fighter_id` | string | UFCStats blue-side fighter ID. |
| `market_key` | string | Canonical market key. |
| `outcome_label` | string | Canonical outcome label. |
| `model_probability` | float | Model probability for this exact outcome. |
| `is_model_pick` | bool | True if this outcome is the model's highest-probability pick for the fight/market. |
| `model_pick` | string | Outcome label selected by the model for the fight/market. |
| `model_confidence` | float | Probability assigned to the model pick. |
| `passes_model_data_quality` | bool | True if input matching/data quality passes model-level gates. |
| `passes_feature_validation` | bool | True if feature row passes validation checks. |

### Recommended Columns

| Column | Type | Description |
|---|---:|---|
| `model_artifact_dir` | string | Directory containing model artifacts. |
| `model_config_path` | string | Config YAML used for this model. |
| `selected_event_id` | string | Event ID selected by dashboard/workflow. |
| `selected_model_id` | string | Model ID selected by CLI/env/dashboard. |
| `commence_time` | timestamp/string | Event/fight start time if known. |
| `outcome_side` | string | `red`, `blue`, `positive`, `negative`, or class label. |
| `threshold` | float | Decision threshold used, when applicable. |
| `nonzero_feature_count` | int | Number of non-zero model input features. |
| `zero_feature_pct` | float | Percent of zero-valued input features. |
| `feature_count_expected` | int | Expected feature count from model config. |
| `feature_count_actual` | int | Actual feature count used for prediction. |
| `red_feature_match` | string | Match source for red-side feature row. |
| `blue_feature_match` | string | Match source for blue-side feature row. |
| `feature_match_type` | string | Optional combined feature match classification. |

## Canonical Market Outcome Schema

Recommended path:

```text
data/market/market_outcomes.parquet
```

Recommended snapshot history path:

```text
data/market/market_outcome_snapshots.parquet
```

### Primary Grain

```text
one row per snapshot_run_id / bookmaker / fight_id / market_key / outcome_label
```

### Required Columns

| Column | Type | Description |
|---|---:|---|
| `snapshot_run_id` | string | Unique odds snapshot run identifier. |
| `snapshot_timestamp` | timestamp/string | UTC time when odds were fetched. |
| `source` | string | Odds source, e.g. `the_odds_api`. |
| `bookmaker` | string | Sportsbook name, e.g. `DraftKings`. |
| `market_key` | string | Canonical market key. |
| `event_id` | string | Event identifier when matched. |
| `event_name` | string | Event name. |
| `fight_id` | string | Matched fight identifier. |
| `outcome_label` | string | Canonical outcome label matching prediction output. |
| `american_odds` | float/int | American odds. |
| `decimal_odds` | float | Decimal odds. |
| `implied_probability` | float | No-vig or raw implied probability, depending on configuration. |
| `odds_match_type` | string | Match status, e.g. `matched`, `low_confidence`, `unmatched`. |

### Recommended Columns

| Column | Type | Description |
|---|---:|---|
| `sport` | string | Odds API sport key. |
| `region` | string | Odds API region. |
| `commence_time` | timestamp/string | Market event start time. |
| `red_fighter` | string | UFCStats red-side fighter name. |
| `blue_fighter` | string | UFCStats blue-side fighter name. |
| `provider_event_id` | string | Provider event ID. |
| `provider_market_key` | string | Provider-specific market key. |
| `provider_outcome_label` | string | Provider-specific outcome label before normalization. |
| `matched_market_name` | string | Provider market name matched to canonical market. |
| `matched_outcome_name` | string | Provider outcome name matched to canonical outcome. |
| `odds_match_score` | float | Overall odds match score. |
| `odds_min_single_score` | float | Minimum individual fighter/outcome score. |
| `is_live` | bool | Whether market is live/in-play if provided. |


| `prediction_run_id` | string | Prediction run used. |

| `market_key` | string | Canonical market key. |

## Confidence Semantics

`model_probability` is the probability of the row's outcome.

`model_confidence` is the probability assigned to the model pick for the fight/market.

Example:

```text
Fighter A row: model_probability = 0.64, model_confidence = 0.64, is_model_pick = true
Fighter B row: model_probability = 0.36, model_confidence = 0.64, is_model_pick = false
```

This allows the dashboard to show both:

- probability for each bettable outcome
- confidence in the model's top pick

For EV, always use `model_probability` for the specific outcome row.

---

## EV Semantics

`ev` should be computed from:

```text
model_probability
decimal_odds or american_odds
```

The default interpretation should be ROI per unit stake unless a downstream display field explicitly converts it to dollars.

If the dashboard wants dollar EV per $100 stake, use a separate display field such as:

```text
ev_dollars_100
```

Do not overload `ev` with mixed percentage/dollar meanings.

---

## Display Transformations

Dashboards may pivot outcome rows into cards or side-by-side tables.

For example, a moneyline display card may show:

```text
Fighter A: 64%, -150
Fighter B: 36%, +130
```

But the persisted betting-board artifact should remain outcome-based.

Storage and computation stay normalized; presentation can pivot.

---

## Validation Rules

Prediction outcomes should validate:

- required columns exist
- `model_probability` is between 0 and 1
- each fight/market/model has at least one `is_model_pick = true`
- binary formatter groups should usually sum to approximately 1.0
- multiclass formatter groups should usually sum to approximately 1.0
- `outcome_label` is non-empty
- `market_key` is non-empty

Market outcomes should validate:

- required columns exist
- odds fields are numeric where present
- `implied_probability` is between 0 and 1
- `outcome_label` is non-empty
- `market_key` is non-empty
- matched rows have a non-empty `fight_id`

Betting outcomes should validate:

- joined prediction and market fields exist
- `edge = model_probability - implied_probability`
- official bets require all core quality gates to pass
- official bets require positive EV unless deliberately overridden by documented strategy

---

## Migration Guidance

The legacy system may still use side-based columns during migration.

However, new V2 components should target:

```text
model_outcomes.parquet
market_outcomes.parquet
betting_outcomes.parquet
```

Do not introduce new long-term contracts centered on:

```text
red_model_prob
blue_model_prob
red_american_odds
blue_american_odds
```

Those can exist only as temporary compatibility fields or display pivots.

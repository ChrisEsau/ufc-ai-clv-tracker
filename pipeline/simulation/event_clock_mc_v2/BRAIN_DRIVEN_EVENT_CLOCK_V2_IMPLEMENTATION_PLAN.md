# Brain-Driven Event Clock V2 — Clean Refactor Implementation Plan

Date: 2026-08-24
Branch: `research/weight-class-audit-20260823`
Status: implementation plan only; no simulator code changes in this commit
Source of truth: `BRAIN_DRIVEN_EVENT_CLOCK_V2_CONTEXT.md`

## Objective

Refactor Event Clock V2 into a clean causal simulator with:

- an authoritative standing / clinch / ground timeline;
- fighter-initiated events generated by the Standard Fighter brain;
- event outcomes resolved by mechanics;
- explicit phase legality and transitions;
- diagnosable separation between activity timing, tactical choice, execution, and consequence;
- a clean final codebase with no monkey patches, no long-lived compatibility wrappers, and minimal inheritance.

The refactor should preserve validated upstream FSR information and existing consequence mechanics unless a later approved stage explicitly changes them.

---

# Non-negotiable architecture

The causal execution loop is:

1. Read authoritative fight state.
2. Determine each fighter's next action time from the brain activity model.
3. Advance the fight clock to the next brain-initiated action or round/fight boundary.
4. Brain chooses one legal action family for the acting fighter.
5. Emit that fighter-initiated action event on the timeline.
6. Resolve success/failure using mechanics.
7. Apply explicit state delta and consequences.
8. Record phase/timeline changes.
9. Update recent-memory signals.
10. Repeat.

No independent fighter-action event generator is permitted in the final causal execution path.

# Stage 1 — Authoritative state and phase timeline kernel

## Goal

Create the smallest clean state/timeline core capable of representing real chronological phase exposure.

## Required state

At minimum:

```text
fight_time_seconds
round_number
phase: STANDING | CLINCH | GROUND
phase_started_at
clinch_controller: red | blue | None
ground_controller: red | blue | None
finished
winner
finish_method
```

Existing physiology / stamina / score state should be attached only through explicit fields or composed state records needed by later stages. Do not copy all legacy state indiscriminately.

## Required timeline record

Each phase segment must contain:

```text
start_time
end_time
phase
controller
entry_reason
exit_reason
```

## Required transition functions

Pure or near-pure transition application for:

- round start -> standing;
- standing -> clinch;
- standing -> ground;
- clinch -> standing;
- clinch -> ground;
- ground -> standing;
- ground reversal -> ground with controller flip.

## Tests

Deterministic tests must verify:

- no overlapping segments;
- no negative duration;
- no gaps in active fight time;
- controller fields consistent with phase;
- same timestamp transition closes old segment and opens new segment correctly;
- round boundary closes/open segments correctly;
- seeded deterministic replay produces identical timeline.

## Explicitly out of scope

- brain control;
- action timing;
- FSR translation changes;
- strike/TD mechanics changes;
- predictive calibration.

## Exit gate

A scripted sequence such as:

`standing -> clinch -> ground -> reversal -> escape -> standing`

produces an exact conserved phase timeline and passes all invariants.

# Stage 2 — Typed action event contract and phase legality

## Goal

Define the exact boundary between brain-selected action events and mechanics-resolved outcomes.

## Fighter-initiated event types

Standing:

- stand attack;
- stand counter;
- pressure;
- reset range;
- clinch entry;
- takedown entry.

Clinch:

- clinch strike;
- clinch control;
- clinch takedown;
- break clinch.

Ground top:

- ground strike;
- advance position;
- submission attack;
- control;
- disengage.

Ground bottom:

- escape stand;
- improve position;
- reversal;
- submission attack;
- bottom strike.

## Action event requirements

Each event should identify at minimum:

```text
timestamp
actor
action_family
source_phase
```

Mechanics return a typed resolution containing at minimum:

```text
success / outcome
state_delta
consequence events
```

Do not encode success in the brain event itself.

## Legality layer

A single authoritative legality function/table determines legal action families from:

- phase;
- actor role (top/bottom where relevant);
- any minimum required positional state.

The brain may only receive legal actions.

The engine also validates the selected event before resolution so policy bugs cannot create impossible events.

## Tests

- every legal menu by phase;
- every illegal cross-phase event rejected;
- actor/controller constraints respected;
- mechanics cannot silently reinterpret an illegal event as something else.

## Exit gate

Typed event and legality contracts are stable enough that later brain and mechanics stages can depend on them without wrappers.

## Migration rule

- extract/reuse the formula or stable resolution function through explicit imports/composition;
- do not subclass the legacy engine;
- do not call the entire legacy path and then translate its output;
- do not monkey-patch legacy methods;

## Clinch

Clinch mechanics need explicit initial MVP definitions for:

- entry;
- strike resolution;
- takedown resolution;

- mechanics outcome -> expected state delta;
- success/failure does not originate in policy;

# Stage 4 — Brain activity timing model

## Goal

Add the first causal answer to: "When does this fighter act next?"

## Required separation

Timing and action choice must remain separate APIs.

Conceptually:

```text
sample_next_action_delay(actor, state, capability, memory, rng)
choose_action(actor, state, legal_actions, capability, memory, rng)
```

## MVP timing inputs

Start small:

- population/base activity;
- phase;
- own fatigue;
- own hurt state;
- opponent hurt state;
- late-round/fight urgency.

Do not add dozens of coefficients initially.

## Important diagnostic property

The timing model determines total fighter-initiated action opportunity volume.

It must not silently contain action-family preferences.

## Distribution

Use a simple stochastic waiting-time model with interpretable expected delay. Candidate families include exponential or gamma/lognormal waiting times, but select one based on desired behavior and reproducibility rather than convenience.

The first implementation should document:

- expected delay under neutral state;
- how fatigue lengthens/changes delay;
- how urgency/opponent hurt shortens delay;
- minimum/maximum guards if needed.

## Tests

Synthetic magnitude tests for:

- neutral activity;
- fatigue slows activity;
- finishing opportunity increases activity;
- late-behind urgency increases activity;
- ahead/low-risk state does not accidentally create frantic action rate;
- timing RNG reproducibility.

## Exit gate

Timing behavior is directionally sane and independently auditable from action choice.

# Stage 6 — Causal engine loop

## Goal

Join timing, action selection, mechanics, and timeline into one authoritative single-path causal execution loop.

## Scheduling model

Each fighter has a pending next-action time generated by the brain timing layer.

At each loop:

- select earliest fighter action or round/fight boundary;
- advance continuous state for elapsed time;
- if boundary occurs first, handle boundary and refresh decisions as required;
- if fighter action occurs first, ask brain for legal action family at that current state;
- emit action event;
- resolve mechanics;
- apply state/consequences;
- update timeline and memory;
- schedule that fighter's next action;
- allow specified state changes to invalidate/resample pending decisions when necessary.

## Important design question to settle during implementation

Whether the opponent's already scheduled next action should be retained or resampled after a major state change.

MVP recommended rule:

- ordinary strike land/miss: retain pending opponent action unless hurt/phase change occurs;
- phase change: invalidate both incompatible pending actions and resample under new phase;
- knockdown/hurt threshold: allow immediate reevaluation/invalidation;
- round boundary: reset/recompute both.

Document exact invalidation rules; do not make them implicit.

## Tests

Scripted seeded single paths verifying event chronology and action ownership.

Critical impossible-sequence regression tests:

- TD lands -> no standing strike 0.4s later unless ground has explicitly ended;
- clinch entered -> no standing-only event until separation/ground transition;
- ground escape -> subsequent ground action invalid unless ground is re-entered.

## Exit gate

One complete fight path can run causally from start to finish with authoritative timeline and all fighter-initiated events coming from the brain.

Validate the causal engine before predictive tuning.

Run a small historical cohort and measure:

- standing + clinch + ground exposure = elapsed fight time;
- no overlap/gaps;
- legal event/phase alignment;
- controller validity.

### Activity

- fighter actions per minute;
- strikes attempted per minute;
- TD attempts per minute;
- clinch entries per fight;
- ground actions per ground minute.

### Phase

- standing share;
- clinch share;
- ground share;
- phase segment duration distribution;
- entries/exits by transition family;
- top control time by fighter.

### Mechanics

- strike landing rates;
- TD completion rates;
- escapes/reversals;
- submission attempts/conversions;
- KD/KO rates;
- fight duration and method shares.

Do not tune to market probabilities at this stage.

## Exit gate

No structural pathologies. Population magnitudes are at least plausibly in the correct range or have clearly localized diagnostic causes.

## Exit gate

# Stage 10 — Preserve/compare frozen mechanics

## Goal

Determine what changed solely because of the new causal timeline/policy architecture versus unintended mechanics drift.

Use targeted equivalence tests where comparable inputs exist.

Examples:

- same standing strike matchup -> same landing formula;
- same TD matchup -> same completion formula;
- same landed strike severity input -> same damage/KD handling;
- same submission input -> same conversion logic;
- same judging observations -> same scoring behavior.

If exact equivalence is impossible because exposure semantics changed, document why rather than forcing an artificial compatibility wrapper.

## Exit gate

Every intentional mechanics difference is documented and approved; accidental drift is removed.

# Standard Fighter V1 — Decision Engine Design

Date: 2026-08-24
Branch: `research/weight-class-audit-20260823`
Status: research/design only; no Event Clock mechanics integration

> **Integration source of truth:** the later brain-driven Event Clock V2 refactor is governed by `BRAIN_DRIVEN_EVENT_CLOCK_V2_CONTEXT.md` and `BRAIN_DRIVEN_EVENT_CLOCK_V2_IMPLEMENTATION_PLAN.md`. Where this older document discusses shadow integration, policy ticks beside an independently generated Event Clock path, or any other integration assumption that conflicts with the newer causal contract, the newer documents supersede it. The agreed causal ownership is: **brain generates fighter-initiated timeline events; mechanics resolve their outcomes.**

## Objective

Build a small, generic MMA decision layer that answers:

> Given what is happening right now, what should a competent generic fighter try next?

The decision layer must be separate from capability and consequence.

Architecture:

`STANDARD FIGHTER POLICY -> ACTION / PHASE INTENT -> EXISTING TRANSITION CONTEST -> FSR / EXISTING CONSEQUENCE`

It must not replace FSR, retune Event Clock mechanics, or learn fighter-specific behavior from round aggregates.

## External references

### MMA Tycoon

Useful concepts:

- baseline tactical sliders define preferences rather than outcomes;
- some sliders are absolute, while others include common-sense overrides;
- ground actions are position-aware so the fighter avoids nonsensical choices;
- fighters can adapt from prefight expectations toward what is actually happening;
- fighters can become more aggressive when losing late and more cautious when winning late;
- follow-down decisions after knockdowns depend on opponent vulnerability, ground advantage, and ground aggression.

### EA Sports UFC

Useful concepts seen in published AI update notes:

- style-specific AI tendencies;
- contextual takedown/clinch triggers;
- cage awareness;
- grapple choices after successful defense;
- strike-choice awareness while advancing;
- different behavior for standup- versus grappling-oriented fighters;
- persistent damage can change later wrestling viability.

These references support a compact rule/utility policy rather than a large learned policy model.

## Core principle

The standard fighter is not an archetype and is not a scripted personality.

Every fighter starts with the same rational decision framework.

Fighter traits and matchup capability change the utility of available actions.

Example:

- If both fighters are being outstruck, both recognize that standing is currently unfavorable.
- A strong wrestler will see a takedown as a much better alternative than a weak wrestler.
- A strong clinch fighter may choose clinch pressure instead.
- A weak grappler may prefer range reset, countering, or higher-risk striking.

Same brain. Different capabilities.

## V1 decision frequency

Do not make a strategic decision on every strike.

Use a slower `policy_tick` than the mechanical event clock. V1 should evaluate intent at meaningful state changes and/or short fixed windows.

Suggested initial triggers:

- phase transition;
- knockdown / hurt event;
- takedown attempt resolved;
- clinch entry resolved;
- ground position materially changes;
- every short standing decision window;
- late-round / late-fight urgency threshold crossed.

The exact tick length is a calibration parameter for later validation, not part of the frozen Event Clock mechanics.

## V1 observable state

Keep the initial state intentionally small.

### Fight phase

- `phase`: standing / clinch / ground
- `ground_position` when relevant
- `cage_pressure`: neutral / self_back_to_cage / opponent_back_to_cage

### Recent effectiveness

Use short rolling state already generated by the simulation rather than historical round aggregates.

- recent clean/landed strike differential
- recent damage differential
- recent knockdown / hurt indicator
- recent TD attempts and completions
- recent TD defense success
- recent control success
- recent inability to escape / advance

### Physical state

- own stamina / fatigue
- opponent estimated fatigue if represented
- own damage / durability state
- opponent damage / vulnerability state

### Fight context

- time remaining in round
- time remaining in fight
- coarse score state: ahead / close / behind

V1 does not need perfect knowledge. The policy reads the simulator state available to the fighter abstraction.

## Action / intent space

Keep actions at tactical-objective level. Existing mechanics remain responsible for detailed execution.

### Standing

1. `STAND_ATTACK`
2. `STAND_COUNTER`
3. `PRESSURE`
4. `RESET_RANGE`
5. `CLINCH_ENTRY`
6. `TAKEDOWN_ENTRY`

### Clinch

1. `CLINCH_STRIKE`
2. `CLINCH_CONTROL`
3. `CLINCH_TAKEDOWN`
4. `BREAK_CLINCH`

### Ground top

1. `GROUND_STRIKE`
2. `ADVANCE_POSITION`
3. `SUBMISSION_ATTACK`
4. `CONTROL`
5. `DISENGAGE`

### Ground bottom

1. `ESCAPE_STAND`
2. `IMPROVE_POSITION`
3. `REVERSAL`
4. `SUBMISSION_ATTACK`
5. `BOTTOM_STRIKE`

V1 should only expose intents that the current phase can realistically execute.

## Decision model

Use utilities, not hard deterministic rules.

For each legal action `a`:

`utility(a) = base(a) + capability(a) + matchup(a) + state_response(a) + urgency(a) + small_noise`

Then convert utilities to probabilities with a softmax or similar bounded stochastic chooser.

This preserves Monte Carlo variation while still making fighters respond rationally.

## 1. Base preference

Base preference is a neutral population prior for the current phase.

It represents what a generic UFC fighter tends to try when nothing important is happening.

Do not derive this from one fighter's historical behavior.

Population action priors may later be estimated from event-level data or calibrated against aggregate UFC phase/action frequencies.

## 2. Capability / matchup value

FSR and existing matchup mechanics determine whether an alternative is attractive.

Examples:

- high standing offense versus weak standing defense -> raise standing utility;
- high TD offense versus weak TD defense -> raise TD-entry utility;
- poor TD matchup -> reduce TD-entry utility;
- strong top-ground offense after a successful TD -> raise stay-ground / ground-offense utility;
- strong submission capability in a favorable position -> raise submission utility.

Important: capability changes desirability but does not directly force the action.

## 3. State-response layer

This is the core Standard Fighter behavior.

### A. Winning striking exchanges

If own recent striking effectiveness and damage are clearly favorable:

- increase `STAND_ATTACK` / `STAND_COUNTER` according to current initiative;
- reduce voluntary `TAKEDOWN_ENTRY` and `CLINCH_ENTRY` unless those are even stronger matchup routes;
- avoid unnecessary phase changes.

Interpretation: "I'm touching this guy up; stay here."

### B. Losing striking exchanges

If opponent recent striking effectiveness or damage are clearly favorable:

- reduce willingness to remain in the same open exchange;
- raise `RESET_RANGE`;
- raise `CLINCH_ENTRY` when clinch matchup is viable;
- raise `TAKEDOWN_ENTRY` when wrestling matchup is viable;
- if badly hurt, strongly prioritize survival/reset/control rather than ordinary offense.

Interpretation: "I'm getting hit; change the problem."

### C. Opponent hurt / vulnerable

If opponent is hurt or recently knocked down:

- increase finishing pressure;
- increase aggressive striking if standing;
- follow to ground only when opponent vulnerability plus own ground capability makes that attractive;
- do not automatically abandon an elite standing advantage to enter a weak ground matchup.

### D. Own hurt / vulnerable

If own fighter is hurt:

- reduce open-exchange aggression;
- increase reset, clinch, control, or viable takedown utility;
- reduce high-variance actions unless late-fight desperation overrides survival.

### E. Wrestling success

If recent TD attempts succeed efficiently:

- increase future TD-entry utility;
- increase pressure/clinch routes that create TD opportunities;
- if top control/ground offense is also effective, reinforce maintaining ground phase.

### F. Wrestling failure

If repeated TD attempts fail:

- reduce TD-entry utility;
- magnitude depends on energy cost, failure streak, and alternative options;
- do not set TD probability to zero: a wrestler may still have no better route.

### G. Defensive wrestling success

After successfully denying an opponent's wrestling entry:

- optionally increase immediate offensive initiative;
- raise strike/counter utility while opponent is resetting;
- for wrestlers, a counter-wrestling opportunity may become attractive.

### H. Cage state

Opponent back to cage:

- raise pressure, clinch, and appropriate TD-entry utility.

Own back to cage:

- raise escape/reset utility;
- lower actions that require conceding more positional pressure unless deliberately countering.

### I. Ground positional common sense

Position is a hard legality / common-sense modifier.

Examples:

- mounted bottom fighter should favor survival, escape, or position improvement over low-value offense;
- dominant top fighter should not voluntarily stand unless standing value is substantially better;
- submission utility rises with dominant submission-capable positions;
- escape utility rises on bottom and when ground matchup is poor.

This is the clearest lesson from MMA Tycoon's non-absolute ground behavior.

### J. Score and time urgency

Behind late:

- increase variance and finish-seeking utility;
- reduce low-upside control/stalling.

Ahead late:

- reduce unnecessary high-variance exchanges;
- increase safe control/reset choices when capability supports them.

Close fight:

- avoid extreme urgency modifier.

## 4. Memory / adaptation

V1 needs only short memory, not a learned opponent model.

Maintain exponentially decayed or rolling summaries such as:

- standing_exchange_score
- damage_exchange_score
- td_success_recent
- td_failure_recent
- control_success_recent
- opponent_pressure_recent

These should decay toward neutral so one early exchange does not dictate the entire fight.

The policy is therefore responsive without becoming path-dependent forever.

## Fighter individuality in V1

Do not create hard archetypes such as `WRESTLER`, `BOXER`, or `BRAWLER`.

Individuality comes from continuous fighter traits and capabilities.

Two fighters can receive the same state signal but choose differently because their available actions have different expected value.

A later version may add empirically supported preference traits, but V1 should prove the standard decision architecture first.

## What NOT to put in Standard Fighter V1

- no fighter-specific hand-written rules;
- no named-fighter exceptions;
- no RL;
- no neural network policy;
- no sportsbook or market information;
- no round-stat-trained next-action model;
- no changes to damage, stamina, TD, submission, judging, or KO mechanics;
- no downstream probability sharpening;
- no tuning against moneyline residuals during the first behavioral validation.

## Isolation boundary

Implement only as a shadow/research namespace initially, for example:

`pipeline/simulation/event_clock_mc_v2/standard_fighter_v1/`

Suggested modules:

- `state.py` — compact policy-visible state
- `actions.py` — legal tactical intents
- `utility.py` — utility components
- `policy.py` — stochastic choice
- `memory.py` — decayed recent-fight summaries
- `diagnostics.py` — trace why each action was chosen

Do not wire this into the frozen Event Clock execution path until standalone scenario tests pass.

## Required scenario tests before any MC integration

The first validation is behavioral, not predictive.

### Standing

1. Equal matchup / neutral state -> balanced population behavior.
2. Elite striker clearly winning exchanges -> stays standing more often.
3. Same elite striker getting badly outstruck -> alternatives become more likely, but only if viable.
4. Strong wrestler getting outstruck -> TD/clinch response rises sharply.
5. Weak wrestler getting outstruck -> reset/counter rises more than low-EV TD spam.
6. Hurt fighter -> survival choices rise.
7. Hurt opponent -> finishing pressure rises.

### Wrestling

8. Repeated successful TDs -> TD intent rises.
9. Repeated stuffed TDs -> TD intent falls.
10. Stuffed TDs but no viable alternative -> TD intent falls less.

### Cage

11. Opponent on fence + strong wrestling -> clinch/TD pressure rises.
12. Own back on fence -> escape/reset priority rises.

### Ground

13. Dominant top -> control/advance/finish, not nonsensical standups.
14. Mounted bottom -> escape/improve/survive, not low-value offense.
15. Poor ground fighter on bottom -> get-up utility dominates when feasible.

### Score/time

16. Behind late -> urgency and finish-seeking rises.
17. Ahead late -> unnecessary risk falls.

Every test should emit the component utilities so we can see *why* the choice probabilities moved.

## First implementation milestone

Build the isolated policy engine with synthetic scenario inputs only.

No historical fitting.
No Event Clock integration.
No winner-probability comparison.

The milestone passes when the standard fighter makes directionally sensible choices across the scenario matrix and the behavior arises from generic state + capability interactions rather than special-case fighter rules.

After that, run it in shadow mode beside Event Clock V2 and inspect action decisions without allowing it to alter simulated fights.
